# 時間規劃架構

## 分工

| 層         | 檔案                      | 職責                                             |
| ---------- | ------------------------- | ------------------------------------------------ |
| 時間工具   | 規劃核心/time.mjs         | 日期範圍、時段解析、合併與扣除                   |
| 容量       | 規劃核心/capacity.mjs     | 固定事件、休息、上限與緩衝                       |
| 排程       | 規劃核心/scheduler.mjs    | 任務排序、期限、依賴、件數限制                   |
| 資料驗證   | 規劃核心/validation.mjs   | 所有儲存和匯入的資料檢查                         |
| 保存與遷移 | 規劃核心/store.mjs        | 舊格式遷移、獨立副本、保存、復原重做、跨分頁衝突 |
| 計時       | 規劃核心/timer.mjs        | 專注與休息狀態轉換、一次性記錄                   |
| 估時       | 規劃核心/estimates.mjs    | PERT 等估時計算                                  |
| 排程畫面   | 規劃介面/schedule.mjs     | 週清單、月季按週折疊、展開時才建立日卡片         |
| 操作協調   | planner-ui.mjs            | 表單、頁面切換、呼叫核心和保存                   |
| 相容入口   | planner-core.mjs          | 保留既有匯入方式，轉出核心API                    |
| 单檔建置   | scripts/build-planner.mjs | 依模組依賴順序打包離線HTML                       |

核心模組不讀取 DOM 或 localStorage。計時函數接受明確的時間參數，方便重現暫停、延遲返回與跨日情況。保存層注入 storage，不依賴特定瀏覽器。

## 資料更新

讀取副本 → 修改候選資料 → 驗證／遷移 → 成功保存 → 更新已提交狀態。

無效資料與保存失敗不改已提交狀態；損壞的原資料阻止覆寫。提交時比較最後讀取的原始值，拒絕用舊分頁覆寫新紀錄。此機制是衝突偵測，並非跨裝置同步或真正的多程序原子鎖。

普通操作保留本分頁最多20步復原／重做。計時開始或轉換時清除歷史，避免回放造成同一段耗時重複記錄。重新整理後不保留復原堆疊。

舊版 start/end 自動轉成 windows，不改任務內容，保存鍵保留 college-capacity-planner-v1。新增必填欄位或變更語意時，須加入遷移與舊備份測試，不可直接改舊資料。

## 擴充方法

1. 在核心新增純函數與測試；不要把計算寫進按鈕事件。
2. 新欄位先定義驗證與向下相容遷移。
3. 介面只負責輸入、呈現與呼叫保存層。
4. 若改排程策略，保留容量、期限、依賴與不重疊的測試。
5. 同時更新線上與單檔版本。

## 目前限制

排程仍是啟發式建議；確認快照不是鎖定重排。月季容量沿用每週設定，並非已確認的遠期行程。後續可在排程層加入任務類型、不可拆分任務或不同排序策略，在保存層增加 IndexedDB 或同步適配器，不需改寫容量公式。
