# 第二輪架構修補紀錄

這一輪記錄可重現的根因，按問題計數，不把同一根因的多個測試輸入重複計數。已修正 21 項：

1. 備份匯入把進度超過目標十倍的合法計畫誤判為損壞。
2. ICS 標題只處理 LF/CRLF，CR 換行仍可破壞匯出事件邊界。
3. ICS 全天重複事件把 RRULE 截止日輸出成 UTC 日期時間。
4. ICS 全天重複事件把 EXDATE 輸出成帶時區的日期時間。
5. 雲端知識包物件路徑只做字首檢查，沒有拒絕 `..` 路徑段。
6. 雲端二進位下載先完整讀入記憶體，沒有先限制回應大小。
7. 密碼重設期限欄位格式錯誤時可被轉成「無期限」工作階段。
8. 錯題統計使用普通物件作為使用者分類索引，特殊名稱會產生錯誤計數。
9. 決策四象限接受超出 1–5 範圍的分數。
10. 決策階段檢視假設任務狀態一定是陣列，損壞資料會讓整個面板報錯。
11. 期間預算鍵接受多餘日期片段，導致不一致的區間索引。
12. 內建 gzip 知識資料在完整解壓後才檢查大小，可能大量占用記憶體。
13. 使用者匯入 gzip 知識包也在完整解壓後才檢查大小。
14. 規劃器匯入的行程與單次覆寫缺少類別、狀態和備註型別驗證。
15. ICS 匯出重複行程時忽略單次覆寫，改期內容會在匯出後消失。
16. 備份匯入未驗證作答與錯題清單結構，損壞記錄可讓錯題分析面板崩潰。
17. 舊／重複今日任務 ID 會讓移除一筆任務時連帶移除其他同 ID 任務；遷移現在補齊唯一 ID。
18. 已取消的固定事件仍會占用建議排程容量、進入時數統計並產生衝突提醒。
19. 衝突計算遇到損壞行程會拋出低資訊量的型別錯誤，現在回報明確資料驗證訊息。
20. 歷史資料中的缺少／重複 ID 會讓修改或刪除操作選錯多筆；遷移會為記錄集合補齊唯一 ID。
21. 複習狀態以一般物件當作 ID 對照表，特殊 ID（如 `__proto__`）可能寫不進去；改成無原型索引表。

修補後驗證：`node --test tests/*.test.mjs`、`DOM_QA_MODULE=... node --test tests/ui/planner-ui.test.mjs`、規劃器 DOM 與單檔 DOM 檢查、`node scripts/build-planner.mjs`、`git diff --check` 均通過。瀏覽器雲端預覽已在上一輪驗證；本輪仍需將最新修補推到同一個 PR，再於該分支重新載入測試。
